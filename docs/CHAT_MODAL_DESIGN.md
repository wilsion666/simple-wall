# 与AI对话弹窗UI设计文档

## 1. UI结构

### 布局说明
弹窗采用三层结构：**Header / MessageList / InputBar**

```
┌─────────────────────────────────────┐
│ Header (标题 + 模型选择 + 关闭按钮)  │
├─────────────────────────────────────┤
│                                     │
│  MessageList (消息列表，可滚动)     │
│                                     │
│                                     │
├─────────────────────────────────────┤
│ InputBar (输入框 + 发送按钮)         │
│ Error (错误提示，可选显示)           │
└─────────────────────────────────────┘
```

### 组件层级
- **ChatModal** (主容器)
  - **Header** (顶部栏)
    - 标题："与AI对话"
    - **ModelSelect** (模型选择下拉框)
    - 关闭按钮 (×)
  - **Body** (消息区域)
    - **Messages** (消息列表)
      - 用户消息 (右对齐，深色背景)
      - AI消息 (左对齐，白色背景)
      - 空状态提示
  - **Footer** (底部输入区)
    - **Composer** (输入框 + 发送按钮)
    - 错误提示区域

## 2. 模型下拉框

### 模型选项
- **GPT-5.2** (默认值)
- **Gemini 3**
- **Claude**
- **DeepSeek R1**

### 展示方式
- **名字 + 标签**：下拉框显示模型名称（如 "GPT-5.2"）
- 自定义下拉箭头样式（SVG图标）
- 悬停时边框高亮（#0066cc）
- 聚焦时显示蓝色阴影

### 禁用规则
- **生成中不可切换**：当 `isGenerating === true` 时，下拉框禁用
- 禁用状态：
  - `opacity: 0.6`
  - `cursor: not-allowed`
  - `background-color: #f5f5f5`
- 如果用户在生成中尝试切换，显示错误提示："生成中，无法切换模型"，并恢复原选择

## 3. 交互规则

### 切换模型影响范围
1. **当前对话历史**：
   - 切换模型后，提示用户："已切换到 [模型名]"
   - 询问是否清空当前对话（因为不同模型的上下文可能不适用）
   - 用户确认后清空消息列表

2. **后续消息**：
   - 切换后的新消息使用新模型
   - 已发送的消息保持不变（历史记录）

### 提示方式
- **模型切换提示**：使用 `confirm()` 对话框
- **错误提示**：底部红色错误条，3秒后自动隐藏
- **生成中状态**：
  - 输入框禁用
  - 发送按钮禁用
  - 模型选择禁用
  - AI消息显示 "loading" 样式（斜体、灰色）

### 错误提示
- **网络错误**：显示 "错误: [错误信息]"
- **API错误**：显示 "错误: [状态码/错误信息]"
- **生成中切换模型**：显示 "生成中，无法切换模型"
- **无回复内容**：显示 "未收到回复内容"
- 所有错误提示在底部红色条显示，3秒后自动隐藏

### 键盘快捷键
- **ESC**：关闭弹窗
- **Enter**：发送消息
- **Shift + Enter**：换行

## 4. 组件清单

### ChatModal (主组件)
**文件**: `components/chat-modal.js`

**职责**：
- 管理弹窗的打开/关闭
- 协调子组件交互
- 处理API调用（流式响应）
- 管理消息状态

**主要方法**：
- `open()` - 打开弹窗
- `close()` - 关闭弹窗
- `sendMessage()` - 发送消息并处理流式响应
- `onModelChange(newModel)` - 处理模型切换
- `addMessage(role, content, isLoading)` - 添加消息到列表
- `updateMessage(messageDiv, content)` - 更新流式消息内容
- `clearMessages()` - 清空消息列表
- `showError(message)` - 显示错误提示

### ModelSelect (模型选择)
**位置**: Header 中的 `<select>` 元素

**功能**：
- 显示当前选择的模型
- 提供4个模型选项
- 禁用状态管理（生成中）
- 切换时触发 `onModelChange()`

**样式**：
- 自定义下拉箭头
- 悬停/聚焦高亮
- 禁用状态样式

### Messages (消息列表)
**位置**: Body 中的 `.chat-messages` 容器

**功能**：
- 显示用户和AI消息
- 支持流式更新（逐字符显示）
- 自动滚动到底部
- 空状态提示

**消息样式**：
- **用户消息**：右对齐，深色背景 (#111)，白色文字
- **AI消息**：左对齐，白色背景，阴影
- **加载中**：斜体、灰色文字

### Composer (输入框)
**位置**: Footer 中的 `.chat-input-wrapper`

**功能**：
- 多行文本输入
- 自动调整高度（最大120px）
- Enter发送，Shift+Enter换行
- 禁用状态（生成中）

**组件**：
- `<textarea>` - 输入框
- `<button>` - 发送按钮

## 5. MVP范围

### 当前实现
✅ **不接真实模型**，使用 `/api/chat-mock` 模拟API

### Mock API 功能
- **路径**: `/api/chat-mock`
- **方法**: POST
- **请求体**:
  ```json
  {
    "messages": [
      { "role": "user", "content": "..." },
      { "role": "assistant", "content": "..." }
    ],
    "model": "gpt-5.2"
  }
  ```
- **响应**: 流式SSE格式，模拟打字效果（每50ms一个字符）

### Mock响应内容
根据选择的模型返回不同的模拟回复：
- **GPT-5.2**: "这是来自 GPT-5.2 的回复..."
- **Gemini 3**: "这是来自 Gemini 3 的回复..."
- **Claude**: "这是来自 Claude 的回复..."
- **DeepSeek R1**: "这是来自 DeepSeek R1 的回复..."

## 6. 样式特点

### 设计风格
- **参考ChatGPT但更简洁**：
  - 更少的装饰元素
  - 更紧凑的间距
  - 更简洁的颜色方案（黑白灰 + 蓝色强调）

### 颜色方案
- **背景**: #fff (弹窗), #fafafa (消息区域)
- **文字**: #111 (主要), #333 (次要), #999 (提示)
- **强调**: #0066cc (链接/聚焦)
- **错误**: #c00 (错误文字), #fee (错误背景)

### 动画效果
- **弹窗打开**: 缩放 + 淡入 (0.3s)
- **消息添加**: 淡入 + 上移 (0.3s)
- **输入框聚焦**: 蓝色边框 + 阴影

### 响应式
- **桌面端**: 最大宽度800px，居中显示
- **移动端**: 全屏显示，圆角为0

## 7. 使用方式

### 在页面中集成
```html
<!-- 1. 添加打开按钮 -->
<button id="chatModalBtn">与AI对话</button>

<!-- 2. 加载组件脚本 -->
<script src="/components/chat-modal.js"></script>

<!-- 3. 初始化并绑定 -->
<script>
  const chatModal = new ChatModal();
  document.getElementById('chatModalBtn').addEventListener('click', () => {
    chatModal.open();
  });
</script>
```

### 在 index.html 中的集成
已在 `index.html` 的导航栏添加 "与AI对话" 按钮，点击即可打开弹窗。

## 8. 技术实现

### 流式响应处理
使用 Server-Sent Events (SSE) 格式：
```
data: {"content": "字符", "done": false}

data: [DONE]
```

前端使用 `ReadableStream` 逐字符读取并更新UI。

### 状态管理
- `isOpen`: 弹窗是否打开
- `currentModel`: 当前选择的模型
- `isGenerating`: 是否正在生成回复
- `messages`: 消息历史数组

### 错误处理
- 网络错误捕获
- API错误状态码处理
- 用户友好的错误提示
- 自动恢复UI状态
