# DeepSeek 对话功能自测步骤

## 前置准备

### 1. 获取 DeepSeek API Key
- 访问 https://platform.deepseek.com/
- 注册/登录账号
- 在控制台获取 API Key（格式：`sk-...`）

### 2. 配置环境变量

#### 本地开发（使用 Vercel CLI）
```bash
# 安装 Vercel CLI（如果未安装）
npm i -g vercel

# 在项目根目录创建 .env.local
echo "DEEPSEEK_API_KEY=sk-your-actual-key-here" > .env.local
```

#### 或使用 Vercel 控制台
1. 登录 https://vercel.com
2. 进入项目设置 → Environment Variables
3. 添加 `DEEPSEEK_API_KEY`，值为你的 API Key
4. 选择环境（Production、Preview、Development）
5. 保存并重新部署

## 本地测试步骤

### 1. 启动本地开发服务器
```bash
# 使用 Vercel CLI
vercel dev

# 或使用其他静态服务器（但 API 路由需要 Vercel 环境）
# 例如：npx serve .
```

### 2. 访问聊天页面
- 打开浏览器访问：http://localhost:3000/chat.html
- 或访问首页，点击导航栏的 "DeepSeek 对话" 按钮

### 3. 测试正常对话
1. 在输入框输入："你好，请介绍一下你自己"
2. 点击"发送"按钮或按 Enter 键
3. **预期结果**：
   - 用户消息立即显示在聊天界面
   - 显示"思考中..."的加载状态
   - 几秒后显示 AI 的回复内容
   - 消息格式正确（用户消息在右侧，AI 消息在左侧）

### 4. 测试多轮对话
1. 继续发送："你能帮我写一段代码吗？"
2. **预期结果**：
   - AI 能够理解上下文，给出相关回复
   - 对话历史正确显示

### 5. 测试错误处理

#### 测试 401 错误（API Key 错误）
1. 临时修改环境变量为错误的 API Key
2. 发送一条消息
3. **预期结果**：
   - 前端显示错误提示："错误：API 密钥错误（401）"
   - 错误信息清晰可见

#### 测试网络错误
1. 断开网络连接
2. 发送一条消息
3. **预期结果**：
   - 前端显示："网络错误：..."
   - 用户消息不会保留在历史中（因为请求失败）

#### 测试空输入
1. 不输入任何内容，直接点击发送
2. **预期结果**：
   - 按钮被禁用，不会发送请求
   - 或输入框提示不能为空

### 6. 测试 UI 交互
1. **输入框自动调整高度**：
   - 输入多行文本，观察输入框是否自动扩展
   - 最多扩展到 200px 高度
2. **滚动行为**：
   - 发送多条消息后，页面应自动滚动到底部
3. **响应式设计**：
   - 在移动设备或缩小浏览器窗口时，界面应正常显示

## 常见问题排查

### 问题：API 返回 500 错误
**排查步骤**：
1. 检查 Vercel 函数日志（Vercel Dashboard → Functions → View Logs）
2. 确认环境变量 `DEEPSEEK_API_KEY` 已正确配置
3. 确认 API Key 格式正确（以 `sk-` 开头）

### 问题：前端显示"网络错误"
**排查步骤**：
1. 打开浏览器开发者工具（F12）→ Network 标签
2. 查看 `/api/chat` 请求的状态码和响应
3. 检查 CORS 设置（Vercel 默认允许）

### 问题：消息发送后无响应
**排查步骤**：
1. 检查浏览器控制台是否有 JavaScript 错误
2. 检查 Network 标签中请求是否成功
3. 查看 Vercel 函数日志

### 问题：环境变量不生效
**排查步骤**：
1. 确认 `.env.local` 文件在项目根目录
2. 确认使用 `vercel dev` 启动（不是其他静态服务器）
3. 在 Vercel 控制台确认环境变量已保存
4. 重新部署项目
